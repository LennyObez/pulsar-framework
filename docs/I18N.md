# Internationalization (i18n)

Pulsar provides a complete translation and localization system with ICU MessageFormat support, locale negotiation, number/date/currency formatting, build-time key extraction, and catalog linting.

## Configuration

Create `config/i18n.php` to enable the i18n module:

```php
return [
    'default_locale' => 'en',
    'supported_locales' => ['en', 'fr', 'de', 'es'],
    'fallback_locales' => ['en'],
    'catalog_path' => 'lang',
    'regulated' => false,
    'max_supported_locales' => 50,
    'strict_mode' => false,
];
```

### Config Fields

| Field                   | Type           | Default  | Description                                                           |
| ----------------------- | -------------- | -------- | --------------------------------------------------------------------- |
| `default_locale`        | `string`       | `'en'`   | Default locale when no negotiation match                              |
| `supported_locales`     | `list<string>` | `['en']` | Locales the application supports                                      |
| `fallback_locales`      | `list<string>` | `['en']` | Fallback chain when a key is missing in the target locale             |
| `catalog_path`          | `?string`      | `null`   | Path to translation catalogs (relative to project root)               |
| `regulated`             | `bool`         | `false`  | When `true`, ext-intl is required at boot                             |
| `max_supported_locales` | `int`          | `50`     | Maximum supported locales (safety bound)                              |
| `strict_mode`           | `bool`         | `false`  | When `true`, missing translations throw `MissingTranslationException` |

### Environment Variable Overrides

| Variable         | Overrides                                      |
| ---------------- | ---------------------------------------------- |
| `APP_LOCALE`     | `default_locale`                               |
| `I18N_REGULATED` | `regulated` (accepts `1`, `true`, `yes`, `on`) |

## Translation Catalogs

Catalogs store translation messages organized by locale and domain.

### PHP Catalogs

Create files at `lang/{locale}/{domain}.php`:

```php
// lang/en/messages.php
return [
    'welcome' => 'Welcome to {appName}!',
    'items_count' => '{count, plural, =0{No items} one{# item} other{# items}}',
    'terms_html' => [
        'message' => 'Agree to our <a href="/terms">Terms</a>.',
        'html_safe' => true,
        'context' => 'Registration page footer',
        'max_length' => 200,
    ],
];
```

### JSON Catalogs

Create files at `lang/{locale}/{domain}.json`:

```json
{
  "welcome": "Bienvenue sur {appName} !",
  "items_count": "{count, plural, =0{Aucun élément} one{# élément} other{# éléments}}"
}
```

### Entry Formats

Translation entries can be either:

- **Simple string** - the message text directly
- **Rich array** - with metadata:
 - `message` (required) - the message text
 - `html_safe` - marks the entry as containing intentional HTML
 - `context` - developer context for translators
 - `max_length` - enforced by the linter

### Chain Catalog

When `catalog_path` is set, Pulsar creates a `ChainCatalog` that tries PHP files first, then JSON files. The first catalog containing a key wins.

### Performance

- Domains are loaded lazily on first access and cached in-memory
- Missing domain files are negatively cached to avoid repeated filesystem probes
- In persistent runtimes (RoadRunner, FrankenPHP), catalogs stay loaded across requests

## Translator

The `TranslatorInterface` is the primary API for translating messages:

```php
use Pulsar\I18n\TranslatorInterface;

final class WelcomeController
{
    public function __construct(
        private readonly TranslatorInterface $translator,
    ) {}

    public function index(): Response
    {
        $message = $this->translator->translate('welcome', ['appName' => 'Pulsar']);
        // "Welcome to Pulsar!"

        $count = $this->translator->translate('items_count', ['count' => 3]);
        // "3 items"
    }
}
```

### Method Signatures

```php
interface TranslatorInterface
{
    public function translate(
        string $key,
        array $parameters = [],
        ?string $locale = null,
        string $domain = 'messages',
    ): string;

    public function getLocale(): string;
    public function setLocale(string $locale): void;

    public function has(
        string $key,
        ?string $locale = null,
        string $domain = 'messages',
    ): bool;
}
```

### Translation Fallback Chain

When resolving a key, the translator searches through:

1. The target locale's own chain (e.g., `fr_CA` then `fr`)
2. Config `fallback_locales` (e.g., `['en']`)
3. If still not found:
  - **Default mode**: returns the key as-is
  - **Strict mode**: throws `MissingTranslationException`

### Helper Functions

Global `__()` and `trans()` functions are available when the i18n module is wired:

```php
echo __('welcome', ['appName' => 'Pulsar']);
echo trans('items_count', ['count' => 5], 'fr', 'messages');
```

These resolve via `Translator::getGlobalInstance()`. If i18n is not booted, they throw `I18nException::notBooted()`.

## Locale Value Object

The `Locale` class parses BCP 47 locale tags:

```php
use Pulsar\I18n\Locale;

$locale = Locale::parse('fr_CA');
$locale->tag;           // 'fr_CA'
$locale->language;      // 'fr'
$locale->region;        // 'CA'
$locale->fallbackChain(); // ['fr_CA', 'fr']
$locale->isRtl();       // false

$arabic = Locale::parse('ar');
$arabic->isRtl();       // true (ar, he, fa, ur)
```

## Locale Negotiation

The `LocaleMiddleware` automatically negotiates the best locale for each HTTP request.

### Priority Order

1. **Query parameter** `?locale=xx` (highest priority)
2. **Request attribute** `_locale` (set by route parameter)
3. **Accept-Language header** (RFC 7231, quality-sorted)
4. **Config default** (lowest priority)

Each candidate is matched against `supportedLocales`: exact match first, then language-prefix match (e.g., `fr_CA` matches supported `fr`, and vice versa).

### Safety Bounds

- Accept-Language parsing caps at 20 tokens
- Malformed `q=` values are treated as `q=0`
- No exceptions thrown for malformed input

## Message Formatting

### ICU MessageFormat (ext-intl)

When ext-intl is available, Pulsar uses ICU MessageFormat for plurals, select, and parameterized messages:

```php
// Plurals
'{count, plural, =0{No items} one{# item} other{# items}}'

// Select
'{gender, select, female{She} male{He} other{They}} liked this.'

// Number formatting in messages
'Price: {price, number, currency}'
```

### Fallback Formatter (no ext-intl)

Without ext-intl, only simple `{name}` placeholder replacement is available. A warning is logged on first use. ICU features like plurals and select are not supported in this mode.

### ext-intl Policy

| Mode          | ext-intl present | Behavior                                        |
| ------------- | ---------------- | ----------------------------------------------- |
| Regulated     | Yes              | Full ICU + all Intl formatters                  |
| Regulated     | No               | **Boot throws `I18nException::intlRequired()`** |
| Non-regulated | Yes              | Full ICU + all Intl formatters                  |
| Non-regulated | No               | Simple placeholders only, warning logged        |

## Number, Date, and Currency Formatting

When ext-intl is available, these formatters are registered in the container:

### NumberFormatterInterface

```php
use Pulsar\I18n\Format\NumberFormatterInterface;

$formatter->format(1234.56);           // "1,234.56" (en)
$formatter->format(1234.56, 'de');     // "1.234,56"
```

### DateFormatterInterface

```php
use Pulsar\I18n\Format\DateFormatterInterface;

$formatter->format(new \DateTimeImmutable('2025-06-15'));
// "June 15, 2025" (en, medium date)
```

### CurrencyFormatterInterface

```php
use Pulsar\I18n\Format\CurrencyFormatterInterface;

$formatter->format(42.99, 'USD');      // "$42.99" (en)
$formatter->format(42.99, 'EUR', 'de'); // "42,99 €"
```

## Console Commands

### `i18n:extract`

Scans PHP source files for translation function calls and outputs a JSON manifest:

```bash
php bin/pulsar i18n:extract
php bin/pulsar i18n:extract -o var/i18n/custom.json
```

Extracts keys from:

- `__('key')` calls
- `trans('key')` calls
- `$translator->translate('key')` calls

Output is deterministic: keys sorted alphabetically, paths normalized to forward slashes.

### `i18n:lint`

Validates translation catalogs for common issues:

```bash
php bin/pulsar i18n:lint
php bin/pulsar i18n:lint -d validation
```

Checks performed:

| Check                    | Severity | Description                                            |
| ------------------------ | -------- | ------------------------------------------------------ |
| HTML in non-safe entries | Warning  | `<tag>` found but `html_safe` not set                  |
| Invalid ICU patterns     | Error    | `MessageFormatter::create()` fails (requires ext-intl) |
| Missing translations     | Warning  | Key exists in one locale but not another               |
| Max-length violations    | Warning  | `mb_strlen` exceeds `max_length` metadata              |
| Orphaned translations    | Warning  | Key in catalog but not in extracted manifest           |

## Validation Integration

`TranslatableViolation` extends `Violation` with translation support:

```php
use Pulsar\Http\Validation\TranslatableViolation;

$violation = new TranslatableViolation(
    field: 'email',
    message: 'The email field is required.',
    translationKey: 'validation.required',
    translationParameters: ['field' => 'email'],
);

// Translate the violation message
$translated = $violation->translate($translator);
```

Default English validation messages ship in `lang/en/validation.php`.

## HTML Safety

The translator returns raw strings only. It does not perform HTML escaping or sanitization. The `html_safe` metadata flag is informational:

- The **linter** uses it to suppress HTML warnings
- **Template engines** use it to decide whether to auto-escape

Escaping is always the view layer's responsibility.
