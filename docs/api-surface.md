# Public API surface — Pulsar Framework

> **Status (2026-04-25, Phase 0 baseline).** Empty by design. The 53 framework
> crates are scaffolded as `lib.rs` placeholders awaiting Phase 1 sprint
> deliveries. No public types, traits, or functions are exposed yet beyond
> the per-crate `VERSION` constant and the standard module skeleton
> (`error`, `prelude`, `sealed`).
>
> This file is the canonical inventory of every `pub` item that escapes the
> crate boundary. It is regenerated by `tools/scripts/regenerate-api-surface.sh`
> (eventually wired to `cargo public-api`) before each tagged release.
> A diff against the previously published surface is required content of
> every release notes entry per Decision 2.32 (semver discipline).

## Why this file exists

Pulsar targets regulated, mission-critical domains where the published
public API is a long-lived contract — not a moving target. Section 2.32
locks the framework into strict semver from `0.1.0` onward, with **zero**
breaking-change tolerance once a crate exits experimental status.

This file plus `cargo public-api` enable mechanical detection of:

- accidental additions (something marked `pub` that should have been `pub(crate)`);
- accidental removals (a deletion that breaks downstream callers);
- type signature drift (parameter reordering, generic relaxation, lifetime tightening);
- trait-bound widening (a `where T: Clone` becoming `where T: Clone + Default`);
- re-export source changes (`pulsar-prelude` re-exporting from a different crate).

## Generation procedure

Two complementary representations are produced and both committed:

### Markdown summary (this file)

Hand-curated section-per-crate listing of every public symbol grouped by
visibility tier (`stable`, `experimental`, `deprecated`). Reviewable by
humans during release-readiness checkpoints.

### Mechanical reference (`docs/api-surface/`)

Per-crate `<crate>.txt` produced by `cargo public-api --simplified`.
The text format is line-oriented and stable across `cargo public-api`
versions, so `git diff` cleanly shows what changed.

```bash
./tools/scripts/regenerate-api-surface.sh
```

The script invokes `cargo public-api` per crate, normalises the output,
and writes one `.txt` file per crate plus an aggregated `INDEX.txt`.
CI compares the regenerated output against the committed copy and fails
the release pipeline on divergence — the maintainer then either
acknowledges the drift (intentional API change → semver bump + this file
updated) or fixes the regression.

## Visibility tiers

Every public symbol is tagged with one of three stability tiers in the
crate-level rustdoc:

| Tier | Meaning | Semver guarantee |
|------|---------|------------------|
| `stable` | First-class, polished surface ready for production use. | Strict semver — no breaking change before MAJOR bump. |
| `experimental` | Reserved tier for `0.x.y` previews — opt-in via the `experimental` cargo feature. | Breaking changes allowed at MINOR bumps; release notes call out every break. |
| `deprecated` | Marked `#[deprecated]` with a `since = "X.Y.Z"` and a forward-pointer to the replacement. | Removed at the next MAJOR bump; minimum two MINOR releases of warning before removal per Decision 2.32. |

Every public item must carry a tier annotation in its rustdoc summary line.
A clippy lint enforces presence of the tag once `pulsar-lint-internal` lands
in Sprint 0.10.

## Phase 0 baseline assertion

As of `v0.0.1-alpha.0` the entire framework public surface fits in this
sentence: each crate exposes `pub const VERSION: &str = env!("CARGO_PKG_VERSION");`.
That fact is verified by `tests/smoke.rs` in every crate.
