# ORM extension

Opt-in entity mapping and persistence layer built on top of Pulsar's [Database Layer](database.md). Provides attribute-based mapping, a read-only query builder, explicit persistence with audit trails, transparent column encryption, and multi-tenant scoping.

## Design principles

- **Explicit persistence**: No implicit Unit of Work or change tracking. All writes go through repositories with a `MutationContext` for audit trail.
- **No lazy loading**: Relations must be declared upfront via `FetchPlan`. Accessing an unloaded relation does not trigger hidden queries.
- **Read-only query builder**: The public query API is read-only (`SELECT`). Insert, update, and delete operations are internal to the repository layer.
- **Fail-fast validation**: SQL identifiers are validated at construction time. Invalid table or column names never reach compiled SQL.

## Configuration

```php
// config/orm.php
return [
    'connection' => 'default',

    'metadata_cache' => [
        'driver' => 'array',       // 'array' or 'file'
        'path'   => '',            // File cache path (when driver = 'file')
    ],

    'encryption' => [
        'enabled'             => false,
        'sub_key_id'          => 5,
        'context'             => 'orm__enc',
        'blind_index_context' => 'orm__bidx',
    ],

    'tenant_column'      => 'tenant_id',
    'soft_delete_column'  => 'deleted_at',
];
```

The ORM config is optional. If `config/orm.php` does not exist, the ORM extension does not register.

## Entities

Entities are plain PHP classes annotated with mapping attributes. The metadata compiler reads attributes at boot time (or from cache) and produces `EntityMetadata` used by all ORM subsystems.

### Defining an entity

```php
use Pulsar\Extension\Orm\Attribute\Column;
use Pulsar\Extension\Orm\Attribute\Id;
use Pulsar\Extension\Orm\Attribute\Table;
use Pulsar\Extension\Orm\Attribute\Timestamps;
use Pulsar\Extension\Orm\Attribute\Version;
use Pulsar\Extension\Orm\Domain\ColumnType;

#[Table(name: 'users')]
#[Timestamps]
class User
{
    #[Id(autoIncrement: true)]
    #[Column(type: ColumnType::BigInt)]
    public int $id;

    #[Column(length: 255)]
    public string $name;

    #[Column(type: ColumnType::String, length: 255)]
    public string $email;

    #[Column(type: ColumnType::Boolean)]
    public bool $active = true;

    #[Version]
    #[Column(type: ColumnType::Integer)]
    public int $version;
}
```

### Mapping attributes

#### `#[Table]` (class-level)

Maps the entity to a database table.

| Parameter | Type      | Default | Description                   |
| --------- | --------- | ------- | ----------------------------- |
| `name`    | `string`  | -       | Table name                    |
| `schema`  | `?string` | `null`  | Database schema (e.g., `crm`) |

#### `#[Id]` (property-level)

Marks the primary key property.

| Parameter       | Type   | Default | Description           |
| --------------- | ------ | ------- | --------------------- |
| `autoIncrement` | `bool` | `true`  | Auto-generated by DB? |

#### `#[Column]` (property-level)

Maps a property to a database column.

| Parameter    | Type         | Default              | Description                    |
| ------------ | ------------ | -------------------- | ------------------------------ |
| `name`       | `?string`    | Property name        | Column name override           |
| `type`       | `ColumnType` | `ColumnType::String` | Column data type               |
| `nullable`   | `bool`       | `false`              | Whether the column is nullable |
| `length`     | `?int`       | `null`               | String/varchar length          |
| `precision`  | `?int`       | `null`               | Decimal precision              |
| `scale`      | `?int`       | `null`               | Decimal scale                  |
| `insertable` | `bool`       | `true`               | Include in INSERT statements   |
| `updatable`  | `bool`       | `true`               | Include in UPDATE statements   |

#### `#[Relation]` (property-level)

Defines a relation to another entity.

| Parameter         | Type           | Default | Description                                       |
| ----------------- | -------------- | ------- | ------------------------------------------------- |
| `type`            | `RelationType` | -       | `BelongsTo`, `HasOne`, `HasMany`, `BelongsToMany` |
| `target`          | `class-string` | -       | Target entity class                               |
| `foreignKey`      | `?string`      | `null`  | Foreign key column (owning side)                  |
| `localKey`        | `?string`      | `null`  | Local key (default: primary key)                  |
| `pivotTable`      | `?string`      | `null`  | Pivot table (BelongsToMany only)                  |
| `pivotForeignKey` | `?string`      | `null`  | FK on pivot referencing this entity               |
| `pivotRelatedKey` | `?string`      | `null`  | FK on pivot referencing related entity            |

#### `#[Version]` (property-level)

Marks the optimistic lock version column. Automatically incremented on each update.

#### `#[Timestamps]` (class-level)

Enables automatic `created_at` / `updated_at` management.

| Parameter   | Type     | Default      | Description |
| ----------- | -------- | ------------ | ----------- |
| `createdAt` | `string` | `created_at` | Column name |
| `updatedAt` | `string` | `updated_at` | Column name |

#### `#[SoftDelete]` (class-level)

Enables soft delete. Soft-deleted entities are excluded from queries by default.

| Parameter | Type     | Default      | Description             |
| --------- | -------- | ------------ | ----------------------- |
| `column`  | `string` | `deleted_at` | Soft delete column name |

#### `#[ValueObject]` (property-level)

Embeds a value object's properties into the owning table.

| Parameter | Type           | Default | Description                     |
| --------- | -------------- | ------- | ------------------------------- |
| `class`   | `class-string` | -       | Value object class              |
| `prefix`  | `string`       | `''`    | Column prefix for embedded cols |

#### `#[CastUsing]` (property-level)

Specifies a custom caster class for type conversion between PHP and database values. The caster must implement `fromDatabase(mixed $value): mixed` and `toDatabase(mixed $value): mixed` as static methods.

### Column types

| `ColumnType` | Description            |
| ------------ | ---------------------- |
| `String`     | VARCHAR (default 255)  |
| `Text`       | Unbounded text         |
| `Integer`    | Standard integer       |
| `SmallInt`   | Small integer          |
| `BigInt`     | 64-bit integer         |
| `Float`      | Floating point         |
| `Decimal`    | Fixed precision (8,2)  |
| `Boolean`    | Boolean                |
| `DateTime`   | Date and time          |
| `Date`       | Date only              |
| `Time`       | Time only              |
| `Json`       | JSON/JSONB             |
| `Uuid`       | UUID string (36 chars) |
| `Binary`     | Binary / BLOB / BYTEA  |
| `Enum`       | Enum-backed VARCHAR    |

### Insert ID strategies

| Strategy | When Used                                          | Behavior                                                       |
| -------- | -------------------------------------------------- | -------------------------------------------------------------- |
| Auto     | `#[Id(autoIncrement: true)]`                       | Database generates the ID; written back to entity after insert |
| UUID     | `#[Id(autoIncrement: false)]` + `ColumnType::Uuid` | Application generates UUID before insert                       |
| Manual   | `#[Id(autoIncrement: false)]`                      | Application sets the ID before insert                          |

## EntityManager

`EntityManager` is the primary entry point for ORM operations.

```php
use Pulsar\Extension\Orm\Gateway\EntityManager;

$em = $container->get(EntityManager::class);
```

### Obtaining repositories

```php
$userRepo = $em->repository(User::class);
```

### Finding entities

```php
// By primary key
$user = $em->find(User::class, 42);

// By primary key or throw
$user = $userRepo->findOrFail(42);

// By criteria
$admins = $userRepo->findBy(['active' => true]);

// Single match by criteria
$user = $userRepo->findOneBy(['email' => 'alice@example.com']);

// Existence and count
$exists = $userRepo->exists(42);
$count = $userRepo->count(['active' => true]);
```

### Persisting entities

All write operations require a `MutationContext` for audit trail.

```php
use Pulsar\Audit\MutationContext;

$context = new MutationContext(
    actor: 'user:alice',
    reason: 'User registration',
    correlationId: 'req-abc-123',
);

// Insert
$user = new User();
$user->name = 'Alice';
$user->email = 'alice@example.com';
$em->persist($user, $context);
// $user->id is now populated

// Update
$user->name = 'Alice Smith';
$em->update($user, $context);

// Delete (soft-delete if configured)
$em->remove($user, $context);
```

### Transactions

```php
$result = $em->transactional(function ($connection) use ($em, $context) {
    $em->persist($order, $context);
    $em->persist($lineItem, $context);
    return $order->id;
});
```

## Query builder

The query builder provides a read-only fluent API for constructing SELECT queries. All identifiers are validated and quoted. Parameters are always bound (never interpolated).

### Basic queries

```php
$users = $em->query(User::class)
    ->where('active', true)
    ->orderBy('name')
    ->limit(25)
    ->getEntities();

$user = $em->query(User::class)
    ->where('email', 'alice@example.com')
    ->firstEntity();
```

### Raw row queries

For queries that don't need entity hydration:

```php
$rows = $em->rawQuery()
    ->from('audit_log')
    ->where('action', 'login')
    ->orderBy('created_at', SortDirection::Desc)
    ->limit(100)
    ->get();

foreach ($rows->rows as $row) {
    $actor = $row->getString('actor');
}
```

### Where clauses

```php
$builder
    ->where('status', 'active')                              // Equality
    ->whereOp('created_at', '>=', '2024-01-01')              // Comparison operator
    ->whereNull('deleted_at')                                // IS NULL
    ->whereNotNull('verified_at')                            // IS NOT NULL
    ->whereIn('role', ['admin', 'editor'])                   // IN (...)
    ->whereNotIn('status', ['banned', 'suspended'])          // NOT IN (...)
    ->whereBetween('age', 18, 65)                            // BETWEEN
    ->whereLike('name', LikePattern::startsWith('Alice'))    // LIKE (escaped)
    ->whereRaw(RawExpression::of('LOWER(email) = :e', ['e' => 'bob@example.com']));
```

### Joins

```php
$builder = $em->query(Order::class)
    ->innerJoin('order_items', 'oi', function ($on) {
        $on->on('t0.id', 'oi.order_id');
    })
    ->leftJoin('users', 'u', function ($on) {
        $on->on('t0.user_id', 'u.id');
    });
```

### Aggregates

```php
$agg = $em->query(Order::class)
    ->where('status', 'completed')
    ->aggregate();

$total  = $agg->count();
$sum    = $agg->sum('total_amount');
$avg    = $agg->avg('total_amount');
$min    = $agg->min('total_amount');
$max    = $agg->max('total_amount');
```

### Locking

```php
use Pulsar\Extension\Orm\Domain\LockMode;

$user = $em->query(User::class)
    ->where('id', 42)
    ->lock(LockMode::ForUpdate)
    ->firstEntity();
```

### SQL inspection

```php
$compiled = $em->query(User::class)
    ->where('active', true)
    ->orderBy('name')
    ->toSql();

// $compiled['sql'] - the parameterized SQL string
// $compiled['bindings'] - the named binding values
```

### Soft delete query modifiers

```php
// Include soft-deleted entities
$all = $em->query(User::class)->withTrashed()->getEntities();

// Only soft-deleted entities
$trashed = $em->query(User::class)->onlyTrashed()->getEntities();
```

## LIKE escaping

The `LikePattern` enum provides safe LIKE pattern construction that escapes `%`, `_`, and `\` from user input.

```php
use Pulsar\Extension\Orm\Domain\LikePattern;

LikePattern::startsWith('Alice')   // 'Alice%'    (escaped)
LikePattern::endsWith('.com')      // '%.com'     (escaped)
LikePattern::contains('search')    // '%search%'  (escaped)
LikePattern::raw('A%ce')           // 'A%ce'      (not escaped)
```

Always prefer the named constructors over `raw()` when dealing with user input.

## Repositories

`RepositoryInterface<T>` provides explicit persistence with required audit context.

### API

| Method                            | Description                                 |
| --------------------------------- | ------------------------------------------- |
| `find(id, ?fetchPlan)`            | Find by primary key                         |
| `findOrFail(id, ?fetchPlan)`      | Find or throw `EntityNotFoundException`     |
| `findBy(criteria, ?fetchPlan)`    | Find all matching criteria                  |
| `findOneBy(criteria, ?fetchPlan)` | Find first matching criteria                |
| `query()`                         | Get a `SelectBuilder` for the entity        |
| `insert(entity, MutationContext)` | Insert a new entity                         |
| `update(entity, MutationContext)` | Update (with optimistic lock if configured) |
| `delete(entity, MutationContext)` | Delete (or soft-delete if configured)       |
| `count(criteria)`                 | Count matching entities                     |
| `exists(id)`                      | Check existence by primary key              |

### Optimistic locking

Entities with a `#[Version]` column participate in optimistic locking. On update, the ORM adds a `WHERE version = :currentVersion` condition and increments the version. If no rows are affected, `OptimisticLockException` is thrown.

```php
try {
    $em->update($user, $context);
} catch (OptimisticLockException $e) {
    // Another process modified this entity - reload and retry
}
```

### Batch audit semantics

Every `insert`, `update`, and `delete` operation writes a tamper-evident audit entry via `AuditLogger`. The audit metadata includes:

- Action: `orm.insert`, `orm.update`, `orm.delete`
- Resource: `EntityClass#id`
- Actor, reason, and correlation ID from `MutationContext`
- Table name

## Relations

Relations are declared with `#[Relation]` and loaded via `FetchPlan`. There is no lazy loading.

### Relation types

| Type            | Description                        |
| --------------- | ---------------------------------- |
| `BelongsTo`     | Many-to-one (FK on this entity)    |
| `HasOne`        | One-to-one (FK on related entity)  |
| `HasMany`       | One-to-many (FK on related entity) |
| `BelongsToMany` | Many-to-many via pivot table       |

### FetchPlan

```php
use Pulsar\Extension\Orm\Domain\FetchPlan;

// Load specific relations
$plan = FetchPlan::with(['orders', 'profile']);

// Nested fetch plans
$plan = FetchPlan::withNested([
    'orders' => FetchPlan::with(['lineItems']),
    'profile' => null, // flat load
]);

// No relations
$plan = FetchPlan::none();

// Merge plans
$combined = $planA->merge($planB);
```

### Usage with repositories

```php
$user = $userRepo->find(42, FetchPlan::with(['orders']));

$users = $em->query(User::class)
    ->where('active', true)
    ->withFetchPlan(FetchPlan::with(['profile']))
    ->getEntities();
```

Relations are loaded via batch loading (IN-clause) or join loading, depending on the relation type.

## Schema builder

The schema builder provides a fluent DDL API for creating and modifying tables. It integrates with the migration system and handles dialect-specific type mapping.

### Creating tables

```php
$em->schema()->create('users', function (TableBuilder $table) {
    $table->id();
    $table->string('name');
    $table->string('email', 320)->unique(['email']);
    $table->boolean('active')->default(true);
    $table->json('metadata')->nullable();
    $table->timestamps();
    $table->softDeletes();
    $table->index(['name'], 'idx_users_name');
});
```

### Modifying tables

```php
$em->schema()->table('users', function (TableBuilder $table) {
    $table->string('phone', 20)->nullable();
    $table->index(['phone']);
    $table->dropColumn('legacy_field');
});
```

### Other operations

```php
$em->schema()->drop('temp_table');
$em->schema()->dropIfExists('temp_table');
$em->schema()->rename('old_table', 'new_table');
$em->schema()->hasTable('users');       // bool
$em->schema()->hasColumn('users', 'email');  // bool
```

## Encryption

The ORM provides transparent column-level encryption at rest using the framework's libsodium crypto subsystem.

### Marking encrypted columns

```php
use Pulsar\Extension\Orm\Attribute\BlindIndex;
use Pulsar\Extension\Orm\Attribute\Column;
use Pulsar\Extension\Orm\Attribute\Encrypted;
use Pulsar\Extension\Orm\Domain\ColumnType;

#[Table(name: 'patients')]
class Patient
{
    #[Id(autoIncrement: true)]
    #[Column(type: ColumnType::BigInt)]
    public int $id;

    #[Column]
    #[Encrypted]
    #[BlindIndex(column: 'ssn_index', hashLength: 32)]
    public string $ssn;

    #[Column(type: ColumnType::Text)]
    #[Encrypted]
    public string $notes;
}
```

### How it works

- **Write path (dehydration)**: Before INSERT/UPDATE, the `AttributeColumnEncryptor` encrypts the plaintext value using XSalsa20-Poly1305 with a domain-separated subkey derived from `PULSAR_MASTER_KEY`.
- **Read path (hydration)**: After SELECT, the encrypted ciphertext is decrypted back to plaintext transparently.
- **Query guard**: The `EncryptedColumnGuard` prevents using encrypted columns in WHERE or ORDER BY clauses unless a blind index is configured. Attempting to do so throws `EncryptedColumnQueryException`.

### Envelope format

Encrypted column values are stored as:

```
version | nonce | ciphertext
```

- `version`: 1 byte identifying the encryption envelope version
- `nonce`: 24 bytes (XSalsa20-Poly1305 nonce)
- `ciphertext`: Variable length (includes Poly1305 authentication tag)

### Blind index

For equality lookups on encrypted data, configure a `#[BlindIndex]` alongside `#[Encrypted]`. The blind index is a truncated BLAKE2b keyed hash stored in a separate column.

| Parameter    | Type     | Default | Description                            |
| ------------ | -------- | ------- | -------------------------------------- |
| `column`     | `string` | -       | Separate DB column for the blind index |
| `hashLength` | `int`    | `32`    | Truncated hash length in bytes         |

The blind index column stores binary data. Use `Param::binary()` when querying:

```php
use Pulsar\Database\Param;

// The BlindIndexer computes the hash and wraps it as Param::binary()
$blindIndexer = $container->get(BlindIndexer::class);
$hash = $blindIndexer->compute('123-45-6789');

$patient = $em->query(Patient::class)
    ->where('ssn_index', $hash)
    ->firstEntity();
```

### Threat model

Blind indexes enable equality search but have inherent trade-offs:

- **Protected against**: Plaintext recovery from the index alone, brute-force attacks on the full ciphertext.
- **Not protected against**: Frequency analysis (identical plaintext produces identical index), known-plaintext confirmation attacks.
- **Mitigations**: Use adequately long hash lengths (32 bytes default), apply additional access controls, and limit query result exposure.

### Crypto primitives

| Operation        | Algorithm         | libsodium Function                  |
| ---------------- | ----------------- | ----------------------------------- |
| Encryption       | XSalsa20-Poly1305 | `sodium_crypto_secretbox`           |
| Key derivation   | BLAKE2b KDF       | `sodium_crypto_kdf_derive_from_key` |
| Blind index hash | BLAKE2b (keyed)   | `sodium_crypto_generichash`         |

### Encryption configuration

| Key                   | Type     | Default     | Description                            |
| --------------------- | -------- | ----------- | -------------------------------------- |
| `enabled`             | `bool`   | `false`     | Enable column encryption               |
| `sub_key_id`          | `int`    | `5`         | Subkey ID for KDF derivation           |
| `context`             | `string` | `orm__enc`  | KDF context for encryption subkey      |
| `blind_index_context` | `string` | `orm__bidx` | Context for blind index key derivation |

### Subkey rotation procedure

1. Deploy new code that accepts both the old and new `sub_key_id`.
2. Run a migration job that re-encrypts all encrypted columns with the new subkey.
3. Recompute all blind indexes with the new blind index context.
4. Remove the old `sub_key_id` acceptance from the code.
5. Audit log the rotation event with `MutationContext`.

Subkey rotation does not require changing `PULSAR_MASTER_KEY` - only the derived subkey changes.

## Tenancy

The ORM integrates with Pulsar's multi-tenancy system for automatic query scoping and insert enrichment.

### Marking tenant-scoped entities

```php
use Pulsar\Extension\Orm\Attribute\TenantScoped;

#[Table(name: 'invoices')]
#[TenantScoped(column: 'tenant_id')]
class Invoice
{
    // ...
    public string $tenantId;
}
```

| Attribute         | Behavior                                                  |
| ----------------- | --------------------------------------------------------- |
| `#[TenantScoped]` | Auto WHERE filtering + auto INSERT enrichment             |
| `#[TenantShared]` | Explicitly opts out of tenant scoping (for lookup tables) |

### How it works

- **SELECT**: `TenantScopeApplier` adds `WHERE tenant_id = :currentTenantId` to every query on tenant-scoped entities when a tenant context is active.
- **INSERT**: `TenantInsertEnricher` adds the `tenant_id` value to insert data if not already present.
- **Joins**: Tenant scoping is applied to the base table. Join targets retain their own scoping rules.
- **Inactive context**: When `TenantScopeInterface::isActive()` returns false (e.g., system operations), no scoping is applied.

### Tenant column configuration

The tenant column name can be specified per-entity via `#[TenantScoped(column: 'org_id')]` or globally via `config/orm.php`:

```php
'tenant_column' => 'tenant_id',
```

Entity-level configuration takes precedence over the global default.

## unsafeRaw()

`RawExpression` provides an escape hatch for database-specific SQL that cannot be expressed through the query builder.

```php
use Pulsar\Extension\Orm\Domain\RawExpression;

// With parameterized bindings (preferred)
$builder->whereRaw(
    RawExpression::of('LOWER(email) = :email', ['email' => $input]),
);

// As a select expression
$builder->select([
    'id',
    RawExpression::of('COUNT(*) OVER () AS total'),
]);
```

`RawExpression` is marked `#[Internal]` at the builder level. Usage is an explicit opt-in that bypasses identifier validation and quoting. Never pass unsanitized user input directly into the SQL string.

## Binary parameter binding

The `Param::binary()` value object ensures binary data is bound correctly to PDO with `PDO::PARAM_LOB`. This is used internally by the blind indexer and available for application code:

```php
use Pulsar\Database\Param;

$connection->query(
    'SELECT * FROM tokens WHERE hash = :hash',
    ['hash' => Param::binary($binaryHash)],
);
```

## Safety guarantees

- **Identifier validation**: All table and column names are validated against `[a-zA-Z_][a-zA-Z0-9_.]*` at construction time. Invalid identifiers throw `QueryBuilderException`.
- **Identifier quoting**: All identifiers are quoted per-dialect (backtick for MySQL, double-quote for PostgreSQL/SQLite).
- **Parameterized queries**: All user values are bound via named parameters. No string interpolation.
- **Encrypted column guard**: Queries on encrypted columns without a blind index are rejected at build time.
- **Optimistic locking**: Version-based concurrency control prevents silent data loss.
- **Audit trail**: Every write operation is logged with actor, reason, and correlation context.
